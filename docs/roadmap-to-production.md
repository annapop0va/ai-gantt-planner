# Roadmap развития AI Gantt Planner

Этот документ — продуктовый roadmap, а не технический backlog. Для каждого направления важнее объяснить проблему и пользовательскую ценность, чем перечислить задачи. Здесь нет сроков и оценок разработки: они не оценивались, и указывать Q1/Q2/Q3 или конкретные даты было бы гаданием, а не планированием.

Краткая версия того, что уже сделано и почему, — в README ([«Roadmap»](../README.md#roadmap)); здесь — что дальше и зачем.

## 1. Что уже доказано MVP

Текущая версия проверяет один сквозной сценарий:

Excel import → построение плана → изменение естественным языком → безопасное применение через MCP/ChangeSet → deterministic rescheduling → обновление диаграммы Ганта → Excel export.

Это подтверждает три вещи: pipeline от загрузки Excel до AI-редактирования и экспорта работает целиком, LLM можно безопасно ограничить ролью «предложить изменение» без права быть источником истины по датам, и deterministic scheduling позволяет доверять результату AI-команды без ручной проверки расчётов.

Дальше задача не «добавить больше функций», а превратить single-user demo в инструмент, пригодный для постоянной реальной работы — это и определяет приоритеты ниже.

## 2. P0 — сделать MVP пригодным для постоянной работы

- **Persistent storage вместо `InMemoryProjectStore`** (например, PostgreSQL). Нужен не потому, что «так принято», а потому что сейчас перезапуск backend или его «засыпание» на Render уничтожает рабочий проект пользователя — без persistence продукт нельзя использовать между сессиями.
- **Сохранение истории чата вместе с проектом.** Иначе история AI-изменений теряется одновременно с самим проектом.
- **Authentication.** Нужен не как техническая функция сама по себе, а чтобы проект можно было безопасно привязать к конкретному пользователю или команде.
- **Ownership проектов пользователями/командами.** Без этого невозможна многопользовательская работа с разными проектами.
- **Восстановление проектов между сессиями** без повторного ручного импорта Excel.
- **Audit/history изменений.** AI меняет проект, и пользователю важно понимать, кто (человек или AI) и когда что изменил.
- **Production hosting без cold start.** Render Free достаточен для демонстрации, но не для рабочего использования, где ожидание в начале сессии неприемлемо.

## 3. P1 — развитие возможностей планирования

Потенциальные направления:

- дополнительные типы зависимостей помимо Finish-to-Start;
- лаги между задачами;
- праздничные и корпоративные календари, настраиваемые графики работы (configurable work schedules);
- частичная (не только целодневная) длительность задач;
- несколько исполнителей на одной задаче;
- capacity / загрузка команды;
- milestones;
- критический путь (critical path);
- baseline versus текущий план.

Часть этого — прямое расширение уже существующей domain-модели (дополнительные календари, milestones, критический путь). Другая часть — например, несколько исполнителей и частичная длительность — меняет текущие MVP-допущения и должна сначала подтвердиться реальным запросом пользователей, а не добавляться только потому, что технически возможна.

## 4. P2 — развитие AI-помощника

Потенциальные направления:

- preview изменений до их применения;
- confirmation для потенциально рискованных mutations;
- undo / история версий;
- многошаговое (multi-turn) уточнение вместо однократного clarification;
- объяснение последствий изменения;
- анализ рисков плана;
- сценарии «что будет, если»;
- несколько вариантов плана;
- поиск перегруженных исполнителей;
- предложения по оптимизации сроков.

Главный архитектурный принцип MVP при этом не меняется: LLM не становится source of truth для scheduling. Расчёт дат и вся валидация остаются в deterministic domain layer независимо от того, насколько развиваются возможности AI-помощника.

## 5. Надёжность и безопасность AI

- evaluation dataset для команд на естественном языке;
- regression suite для Agent;
- adversarial-кейсы;
- тесты на неоднозначность (ambiguity tests);
- трейсинг вызовов MCP tools;
- структурированное логирование;
- мониторинг provider, latency, cost;
- fallback на другую модель;
- rate limiting;
- идемпотентность mutation-эндпоинтов;
- более развитый audit trail.

По мере роста возможностей AI важно измерять не только качество happy path, но и вероятность ошибочной mutation и качество поведения при сбое — то есть насколько безопасно система ведёт себя, когда уверенности недостаточно.

## 6. UX, совместная работа и интеграции

Потенциальные направления, а не утверждённый список обязательных функций:

- более развитое редактирование диаграммы Ганта — drag-and-drop, zoom, группировка, workload-вид;
- фильтры и поиск по задачам;
- комментарии, история изменений, undo;
- совместная работа, sharing, уведомления;
- гибкий маппинг колонок при импорте Excel;
- интеграции с Jira, YouTrack, Linear, внешними календарями.

Roadmap в этой части должен отталкиваться от пользовательской ценности, а не от желания добавить больше экранов — поэтому ни один из пунктов здесь не считается решённым заранее.

## 7. Что нужно валидировать до разработки

Прежде чем расширять P1–P3, стоит проверить гипотезы, а не считать их доказанными только потому, что MVP технически работает:

- насколько часто пользователи действительно хотят редактировать план естественным языком, а не через привычный UI;
- какие формулировки команд встречаются чаще всего;
- нужен ли явный confirmation перед применением изменения или он будет только мешать;
- какой уровень автономности AI приемлем для пользователя;
- насколько важен именно Excel по сравнению с Jira / YouTrack / другими источниками данных;
- какие функции диаграммы Ганта действительно критичны для повседневной работы;
- что пользователю важнее: скорость редактирования, анализ рисков, автоматическая оптимизация сроков или контроль над загрузкой ресурсов.

Подходящие методы: интервью с пользователями, usability- и prototype-тесты, usage-аналитика, анализ логов команд, качественный фидбэк от пилотных пользователей.

## 8. Приоритеты

| Этап | Цель | Основные изменения |
|---|---|---|
| P0 | Сделать MVP пригодным для постоянной работы | persistence, authentication, audit/history, production hosting без cold start |
| P1 | Улучшить реальное планирование | календари, дополнительные типы зависимостей, workload |
| P2 | Расширить AI-workflow | preview, undo, анализ рисков, сценарное планирование |
| P3 | Совместная работа и интеграции | команды, sharing, внешние системы |

Сроки и оценки трудозатрат в этой таблице намеренно не указаны — они не оценивались.
